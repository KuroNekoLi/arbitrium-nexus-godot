# 戰鬥勝敗判定
> 文件定位：**現行戰鬥規則**。明示「候選」的角色內容及數值尚非正式平衡；規則生效狀態以 [總覽](README.md) 為準。

## 什麼時候決定勝敗？
**不是任一 hit 結束就立刻跳畫面。** 引擎完成當次合法 Action、必要附帶效果與當點觸發，再在約定的 outcome boundary 判定。

1. 若**所有敵人都已敗亡** → `VICTORY`，優先級最高。
2. 否則，若敵人仍有存活而**我方已無HP>0且未退場成員** → `DEFEAT`。包含全倒地、全退場及倒地與退場混合。
3. 否則繼續戰鬥，或落入尚待明確決定的特殊邊界。

## 最容易誤判的例子
**同歸於盡也勝利**：合法一張卡及其必要觸發使最後一個 Boss HP0，同時我方最後存活角色也 HP0。結算完成後敵全滅優先，所以**勝利**，不是平局 `DRAW`。

**終式不能死後補刀**：某人提交終式、預定兩個時點後釋放，但在釋放前 HP0：當下就取消終式排程，不能等未來時點再用本已無效的終式傷害觸發勝利。若終式已**合法釋放完成**才被後續事件擊倒，不得回溯取消已生效的效果。

**全員耗竭真正退場、HP仍大於0、敵人還活**：2026-10-16使用者已核准判 `DEFEAT`。只在完整合法action及必要效果完成後判定；最後終式若同時擊敗最後敵人，仍為 `VICTORY`。舊錄影配置保留原語義，詳 [退場裁決](LAST_SPELL_RETIREMENT_APPROVED_20261016.md)。

## Replay 不變量
相同 Ruleset、ContentVersion、初始狀態、隨機種子及合法 Command Tape，應得到同事件序列／最終狀態 hash。UI 動畫時間、等待玩家看完反應視窗的秒數，都不能改結果。
