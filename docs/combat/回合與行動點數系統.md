# 回合與行動點數系統
> 文件定位：**現行戰鬥規則**。明示「候選」的角色內容及數值尚非正式平衡；規則生效狀態以 [總覽](README.md) 為準。

## 一輪的直觀流程
```text
開戰並洗牌，各人起手4張
→ 玩家階段開始：先結算本時點到期詠唱／狀態及必要勝敗
→ 新階段 AP：共享6加合法修正，扣除先前合法 APDebt（若啟用）
→ 合法角色不足4張的手牌補到4
→ 玩家逐次選角、出牌、普攻、道具、免費換牌或Analyze
→ 結束玩家階段：未花完的 AP 嘗試1:1轉RP
→ Boss依公開Intent進入敵方動作，每個合法動作有 Reaction Window
→ 敵方階段結束：RP清零，狀態到期，進入下一輪或終局
```
玩家可以自行決定各人出手次序；同一角色只要合法、有手牌與資源可以重複行動，**沒有每人兩次的全域限制**。敵人行動與玩家階段結算不得由動畫播放速度決定。

## AP：共用而不是平分
常態 BaseAP = **6**。例：蓮花2、朱音花3、紬花1，總計6。每張卡 AP 消耗依版本化卡牌定義；普通攻擊的 1 AP 是現有**候選配置**，非永遠不變的平衡值。技能若合法「增加AP、返AP、降低AP成本、可變成本、Overload」可使 CurrentAP **大於6**，沒有另一條暗中硬上限。

### 債務與超載（進階）
只有允許 Overload 的卡能在不足 AP 時依法借用差額形成 APDebt。未來階段的共享 AP 先還合法債務，再成為當期 CurrentAP。跨階段債務政策、MaxAPDebt=8 等仍是**候選配置**；特效與支付順序必須由資源規則逐項確認。當前階段普通返 AP 不會自動還既有債，只有明示 `ReduceAPDebt` 的效果可減債。

## 玩家階段結束
未使用 AP 對當次 Enemy Phase 提供 RP，正常 `RP=min(remaining_AP, effective_RP_cap)`，預設 cap=6；AP 無論曾否被強化都不會自動帶去下一玩家階段。此時轉換後玩家 AP 歸零；敵方階段剩 RP 最後歸零。

## 例子
這一階段花掉3 AP，留下3 AP，則通常會進入敵方階段拿到3 RP。敵方若有可 Protect 的單體攻擊，花2 RP 做援護，還剩1 RP 可以做一次合格 Guard。若全隊把6 AP花光，敵方階段沒有自然產生的 RP，除非明文卡牌另有 RP 來源。
