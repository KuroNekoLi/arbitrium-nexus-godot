# 戰鬥系統總覽｜唯一現行閱讀入口

本目錄以**玩家看得懂**的方式描述《Arbitrium Nexus / Astraea》現行三人回合制卡牌 RPG 戰鬥，並附足供 Godot Agent 實作的資料與事件契約。不再以開發階段編號作為章節名稱。

## 先掌握六個規則
1. 三名上場角色，每人**恰好 12 張技能卡（SP）**；各有牌庫、手牌、棄牌堆，終式獨立不佔牌組。
2. 開局各抽 **4 張**；每個玩家階段**不足 4 張才補到 4**；手牌硬上限 **8 張**；沒打出的卡保留；每人每階段免費棄一抽一。
3. 全隊共享每階段基準 **6 AP**，角色個別 MP 不會自動回滿；未用 AP 在階段末嘗試轉為 RP（預設上限 6），RP 供緊接的敵方階段反應。
4. 施法分破棄詠唱（立即、較弱）和完整詠唱（延後、較強）；施法穩定度、Boss 失衡槽和 HP 是不同資源。
5. Boss 公開意圖；玩家用 Protect、Guard、卡牌反應處理攻擊。**有合法反應絕不自動倒數或 Pass**。
6. 終式每角色每戰一次，強制完整詠唱；成功完成效果後耗竭並真正退場，不再受擊、治療或復活；施放前 HP 歸零則終式立即失效。敵人仍存活且我方已無存活在場成員就敗北（包括全退場或退場與倒地混合）；合法行動造成同歸於盡，**敵全滅優先判勝利**。見[2026-10-16 核准紀錄](LAST_SPELL_RETIREMENT_APPROVED_20261016.md)。

## Agent／程式開發入口
**工作順序**：根目錄 [AGENTS.md](../../AGENTS.md) → 本 README → 要修改的玩家規則 → [戰鬥引擎實作契約](engineering/戰鬥引擎實作契約.md) → [規則與程式對照表](engineering/規則與程式對照表.md) → [待實作與待驗證功能](engineering/待實作與待驗證功能.md) → 真實程式與測試。禁止只讀圖鑑就自行補足未決規則。

**權威分級**：
- **已確認**：使用者明確決策（如12張、AP6、終式失效、無反應倒數、主角初期劍士及通用基礎魔法資格）。
- **授權預設**：為落地而定義的可測試細節（如傷害最終 floor 與交換牌事件）。可作實作契約，但不等於每個數字由使用者核准。
- **內容候選／平衡候選**：三人具體名字、能力值、31張卡的成本／倍率、3招終式、Boss HP 與技能等；允許以版本化 fixture 先開發、測試，**不可稱最終數值**。
- **待決**：列於工程缺口表；不要自行變更玩法。歷史原始核准與報告保存於 [archive](archive/README.md)。

## 現行程式與舊系統界線
- 正式執行入口：`res://scenes/battle/lv40_playable_battle.tscn`；唯一戰鬥狀態是 M1～M5 Domain 和 Lv40 內容。八卡原型及四個過渡用 smoke 殼與 G0 工作流程已退役。
- 角色、能力、12張牌組與終式：`resources/combat/rosters/lv40_party_v0_3.json`。A/B/C 只是戰鬥槽位，**不等於固定姓名**；角色資料與技能、翻譯、美術及卡牌資格必須同步。新版圖形配牌編輯器、持久化存檔及五人上場尚未完成。
- `scenes/ui/hero_roster_item.tscn` 是新 `PartyStatusPanel` 仍在引用的**現役 HUD 元件**，即使個別驗證名稱仍含 `legacy` 也不能一概刪除。
- **已交付的清理不等於 CI 或實機通關**；回歸證據須逐次核對實際提交／Actions。規範索引見[程式對照](engineering/規則與程式對照表.md)，退役清單見[工程紀錄](engineering/舊系統退役與驗收紀錄.md)。
