# 角色培養與戰鬥形態

> 本文件區分**目前已確認的配牌／形態規則**與未決的養成系統；不要為了填空自行寫入新的等級成長曲線、羈絆 Buff 或轉職成本。

## Character、Variant 與 Skin
- `Character` 是人物身分，如朝霧蓮。
- `Variant` 是該人物解鎖的戰鬥形態，允許改基礎HP/MP、能力值、被動、職能標籤、可配置卡的資格和專屬終式。
- `Skin` 是純外觀，不應改戰鬥數值、卡牌資格或戰鬥結果的 Domain hash。

**已確認主角方向**：初期朝霧蓮只有劍士職能，後續解鎖其他 Character Variant，才可換不同職能；**未核准戰鬥中自由轉職／移動操作**。

## 裝備技能卡的四種資格
| Eligibility | 意義 |
|---|---|
| `UNIVERSAL` | 所有角色可用，包含最基本魔法攻擊、護盾、治癒卡；**仍須抽到且付費** |
| `ROLE_TAG` | 目前 Variant 的標籤要符合，如 `SWORDSMAN` |
| `CHARACTER` | 限特定人物使用，如 `CHARACTER:ren` |
| `VARIANT` | 限某已解鎖的戰鬥形態 |

換形態後必須執行 `ValidateLoadout`：該角色 Variant 已解鎖、**恰好12張技能卡**、卡ID存在、每個實例合法持有、職能與角色資格合法、終式正確。缺卡不能自動塞假卡。同名卡張數／UR上限未批准全域值，不要自己設2張限制。換純Skin不應改戰鬥邏輯。

## 未來候選，不是現有玩家操作
等級成長表、裝備、卡牌稀有度限制、羈絆加成、主動換位花AP與VC效果、五人隊中的自動後備替補等有設計討論方向，但完整 Domain 事件、失效處理與 UI 流程仍待另案。當前戰場視覺可以是2.5D，這**不等於**新增自由走位。
