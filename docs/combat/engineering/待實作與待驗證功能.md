> 本檔描述可確認的功能邊界及後續工作，不把「有檔案」當作「全部完成」；以最新 HEAD／Actions 及真 Godot 輸出核對。

| 項目 | 狀態 | 後續應處理 |
|---|---|---|
| 舊八卡 Domain、DeckBuilder、main 場景 | **RETIRED_SOURCE**；正式執行入口不引用 | 不恢復舊行為，不新增舊存檔格式相容層；如有外部存檔遷移需求，另提決策 |
| 舊四個相容 smoke / G0 gate | **REMOVED_ON_CLEANUP_BRANCH** | 見退役紀錄；直接用 M1～M5／Lv40 現行驗證 |
| 每人12 SP、起手4、補4、上限8、免費換牌 | **RULE_APPROVED／已有 Domain 與 Lv40 測試** | 對新增角色檢查合法配置與抽牌事件，不讓八卡重新進入內容 |
| Roster JSON 可替換角色／形態／名稱／能力／終式 | **DATA_DRIVEN_SCOPE_IMPLEMENTED** | 更換角色時，同步 i18n、卡牌能力、被動、終式效果、資源與測試；未知技能不能僅靠 JSON 自動生成 |
| 初始三人與 Lv40 Boss、31候選SP及3終式 | **CONTENT_PROVISIONAL** | 逐卡打點、費用、命中、目標、描述與正式內容版本；未納入示範牌組的候選不算已上場 |
| Boss 完整技能 parity、Break、Exposed／Combo | **DOMAIN_SCOPE_EXISTS，完整可玩驗證不足** | 檢查逐 Intent、Break 邊界、Chant 與 Combo 的實戰行為 |
| 中文／英文 i18n | **部分實作，覆蓋仍待驗證** | 角色名、UI 錯誤、技能描述、Last Spell、Boss Intent 都需對齊翻譯 |
| Incapacitated 留場 CG 與卡片、Exhausted 退場 | **UI設計方向／視覺驗收待確認** | UI 不得改變 Domain targetability；確認灰階、人物退場和欄位狀態 |
| 三人以上後備補位、主動換位消耗 AP 和 VC | **FUTURE_DESIGN／非當前引擎實作** | 五人 roster、場上與後備 slot、觸發先後、敵目標有效性需先形成規格 |
| 全員耗竭且 HP>0、敵人仍存活 | **OPEN_DECISION** | 不自行新增 Win/Lose 特例 |
| Analyze 完整情報／Spell Counter／Full Chant Combo | **待逐項確認或擴充** | 需要獨立合法 Command、事件與測試；Counter≠Disruption |
| Replay、固定 seed、100 場壓力測試 | **現行流程保留** | 重構後 CI Full 驗證，失敗時保存 seed／事件／state hash |
| P4 HUD、真渲染截圖及真人可玩性 | **Headless／渲染證據與手動操控分層** | 真正玩家完整打完 Lv40 Boss；GUI 端到端不能由靜態圖代替 |

### 工程驗收規則

- 每個功能用 **RuleID → Domain 命令／事件 → 拒絕負例 → Replay → UI 投影與中英翻譯 → CI** 串起來。
- 快速迭代優先執行 `CI Fast`、`CI Integration`、`CI P4 UI Contracts` 和需要時的 `CI Visual`；`CI Full` 排在 nightly／release／明確手動驗收，不讓每次 push 都跑100場。
- 只以真實測試輸出標註 VERIFIED。規格文件、候選內容、既往成功案例不等於新分支驗收結果。
- 新 agent 先讀 [現行對照](規則與程式對照表.md) 及 [退役紀錄](舊系統退役與驗收紀錄.md)，不得把舊檔案路徑當成待補的模組。
