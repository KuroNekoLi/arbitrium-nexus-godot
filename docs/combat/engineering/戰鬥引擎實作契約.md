# 戰鬥引擎實作契約｜Agent 必讀

> **本檔是工程契約，不是第二套遊戲玩法**。玩家規則以[總覽](../README.md)和各領域中文規格為準。所有候選卡面與數值需版本化。若規格與程式衝突：保留已確認玩法、記差距、先寫測試，不以舊原型反向修改已確認規則。

## Agent每次工作流程
1. 讀根目錄 `AGENTS.md` → `docs/combat/README.md` → 本檔 → 任務對應玩家規則／圖鑑。
2. `git rev-parse HEAD` 並核對 `project.godot`、場景、當前 Godot CLI/版本、現有 CI／測試；**不得沿用上次聊天中的實作進度當成當前事實**。
3. 對照 [規則與程式對照表](規則與程式對照表.md)，搜尋現有 Reducer/Config/API/Tests，列出已完成與缺口，避免再寫第二套架構。
4. 新增功能時先列 `RuleID / Command / State / Events / Negative tests / Replay / Presenter / i18n`；有待決玩法或互相矛盾的規範，停止該項變更並回報可決策方案。
5. 僅以現有 Godot 真實測試、CI、畫面及玩家操作證據報告完成；提交必附結果，不能把文件設計或 Python模擬宣稱已在Godot通關。

## 一條命令流，只有一個真實戰鬥狀態
```text
Godot Battle Scene / input / localization
  → BattleController（actor、card_instance_id、target anchor、expected_event_seq）
  → scripts/domain/m5/integration/m5_domain_resolver.gd
  → M1 State/RNG + M2 Payment/Card ledger + M3 Phase/Reaction
    + M4 Casting + M5 Damage/Break/Boss/Outcome + Lv40 versioned content
  → accepted/rejected + authoritative BattleState + ordered DomainEvents
  → Battle UI Adapter / Presenter / Animation / Combat Log
```
此為**責任劃分的概念示意**，不可直接抄當 runtime API；實際 method／argument／state schema 必須從 HEAD 和 tests 檢查。原則：Domain唯一擁有 HP/AP/MP/RP、卡區、詠唱、Boss決策、傷害、終局與可重播 RNG。UI**只能預覽／提交合法命令並呈現回傳結果**；不得在 Tween完成後自行算第二次傷害或用FPS改成敗。

## 必須守住的數據不變量
- 每場每名有效角色進場**恰好12個合法SP CardInstances**；開手4、每階段不足4補4、手牌硬上限8、免費換1。CardInstance只能在一個 draw/hand/discard/casting/exile 區，不能重複出現；若抽棄牌事件變動要可 replay。
- `LastSpellDefinition` 在獨立槽而非12卡；`CharacterID`、`VariantID`、`CardDefinitionID`、`CardInstanceID`、`CastingInstanceID` 各自唯一而不互用；中文卡名只是 i18n。
- 每次資源與合法性預檢先於支付；非法命令不得改任何 State/Events/RNG。AP共有基線6、合法取得AP無額外硬cap、RP常態cap6且敵方階段末清零、MP各人不自然回滿；所有費用與修正逐事件可追蹤。
- Reaction有合法選項時必須等**明確 Confirm／Pass**；無真實時間自動pass。隊列先記計畫、確認後逐筆JIT重驗；已失效者 `ReactionSkipped` 而不扣費、不棄牌。
- Protect先重導、重新算命中及承受者防禦；Guard再Barrier。Focus Ward只吸收施法穩定度干擾；Break在整張SP完成後判定，不用HP扣減模擬Break；Exposed不得同卡自建自用。
- Full Chant合法CastingInterrupt才可部分退MP；AP、Overload不退；HP0失能取消一般待施放，Last Spell HP0立即Invalidated且連MP也不退，已啟動次數仍用掉。
- 勝敗於合法action boundary；**敵全滅 VICTORY 優先**，沒有DRAW。全員Exhausted但HP>0／敵活仍保留待決特殊邊界，不自行放行。
- 繁體中文＋英文雙語，所有玩家可見文字走 `tr()` 或現有 i18n 接口；新增卡／狀態／Boss／錯誤應有 key，不新增硬編碼顯示字串。

## 內容版控與禁止偷改
目前 `scripts/domain/m5/lv40/lv40_content.gd` 的 `BALANCE_PROVISIONAL` Config 才是**此實作 fixture的具體數值**，中文圖鑑保存候選設計意圖。圖鑑列31普通SP定義，`lv40_content.gd` 現只收 starter 24種，額外 R04/A08/T02/T07/T08 是待實作或待驗證的可配置候選；不能稱已全數可玩。角色名稱／Boss名稱／Lv40倍率不得推論全遊戲已定案。

反制 `Spell Counter` 不等於 `Casting Disruption`；普通護盾 `Barrier` 不等於 `Focus Ward`；即使都有名字相同的函數，也不能因測試 fixture 能跑就宣告跨場景完整實作。

## 測試層級
| 層級 | 必須的可檢驗證據 |
|---|---|
| Domain | 現有headless Test IDs全部回歸、非法命令原子性、100固定seed replay、事件／state hash一致 |
| Integration | 真實場景→Controller→Reducer→事件→UI，沒有Fixture硬改戰鬥結果；正負case |
| Playable | 真人鍵鼠／觸控完成Boss一戰含角色切換、出牌、手牌、Reaction、詠唱、終式、勝／敗 |
| Balance | 多策略與多seed，核心指標、角色貢獻，玩法採納後才標 `BALANCE_ACCEPTED` |
| UX/i18n | 中文／英文同內容、可讀性、不同解析度、失能留場與耗竭灰化/退到不可操作區、操作無倒數 |

文件變動本身不需要聲稱曾執行 Godot 測試；遊戲實作修改才需要真實執行證據與相應CI，並更新 [待驗證功能](待實作與待驗證功能.md)。
