# 術式結構與生命週期｜魔法為何能成立

> **作者技術規格｜V1.0／DIRECTION**。先讀 [總規格](00_MAGIC_SYSTEM_SPEC_V1.md)。例子不是新的技能卡或已實測程式。

## 1. 術式不是一句咒語

想像你要發出一顆追蹤火球：得先決定火球的位置、能量來源、溫度／速度／軌跡，再決定追蹤失去目標時該怎麼辦，以及何時解除。這些有輸入、輸出和依賴的合法步驟，形成 **術式結構**。

它類似食譜或流程圖，但不是只要文字寫得漂亮就能實現。**每一步都必須合乎彼世法則，且具備必要資源。** 一個 術式結構 可以被人記住、寫在魔法書、封裝進法杖或儲存在魔導設備；不同載體不會改變客觀合法性。

## 1.1 正式術語及符號

**「術式結構」**是正式世界觀用語。研究時曾以英文 *Function Graph* 指稱同一概念；本檔的英文檔名為既有連結相容性而保留，**不是另一套新機制**。在抽象公式 `Y = E(F,p,R,K,X)` 中，`F` 仍代表合法術式結構，數學意義不變。

## 2. 設計者應描述的六個部分

| 部分 | 火球術示例 | 驗證問題 |
|---|---|---|
| 輸入與參數 | 目標、方向、輸出、持續時間 | 哪些可動態調整？ |
| 合法前置條件 | 施術距離、媒介、目標狀態 | 不符合時是否不能成立？ |
| 效果來源 | 加熱此世環境、彼世能量的合法輸入等 | 能源／物質不能含糊寫成「憑空」 |
| 執行與共鳴 | 建立並維持火球的必要魔法作用 | 一次完成還是需要持續？ |
| 資源與控制 | Mana、承載、控制介面 | 人或設備能否實際執行？ |
| 終止與失效 | 撞擊、逾時、失去目標、共鳴故障 | 失效後剩餘熱量怎麼辦？ |

具體術式的數學型別、節點語法、能量帳本 **TBD**；不可把下面概念流程當成已核准的遊戲 API。

## 3. 從準備到結束

```text
理解／取得術式
 → 設定合法參數與資源
 → 構築並校準
 → T1：有效干涉成立
 → T2：實際效果執行／呈現
 → T3：仍在運作的干涉終止
 → 普通物理結果可繼續存在
```

**第 15 題 C：DIRECTION。** T1、T2、T3 是作者分析順序，可能非常接近甚至無可觀察的時間差；不等於新增玩家戰鬥階段。未完成合法請求前的思考失誤，不應自動算作有效干涉；若已成立部分有效干涉，後續失敗仍可能有代價。

### 三種生命週期

- **一次完成**：例如完成對水的加熱；術式終止後，水仍可以是熱的。
- **有限程序**：例如依允許的時間與觸發條件執行一連串變化，結束後停止。
- **持續維持**：例如某些防護結界、魔法構造物或仍靠魔法維持的飛行火球；有持續共鳴與資源條件。

施術者死亡是否導致術式消失，**不能一概回答是或否**；必須檢查 術式結構 是否需要持續以該人承載或控制。

## 4. 封裝：為什麼學生也能使用複雜術式？

學院驗證火球術之後，可將大部分內部參數鎖定為安全預設，只露出「目標、方向、強度」等操作介面。新生可能不知道底層推導，仍可以合法施法。

封裝的工程界線：
- **安全預設不是免除法則**；不能省去必要能源、有效共鳴與承載。
- **調參必須有介面**；圖上沒有允許飛行中轉向，不得憑「心念很強」突然轉向。
- 需要新能力時，可以合法改寫 術式結構 或疊加另一個有效控制術式，可能需要新資源及產生新世界負擔。
- 身分、許可與學校規矩由社會處理；不是彼世依姓名給權限。

## 5. 彼世能源、此世能源與永久物質

**第 3–5 題：DIRECTION。** 不同 術式結構 可以採不同合法來源：調整此世既有能量／物質、依法則輸入彼世能量或物質，或在嚴格條件下進行能量—物質轉換。Mana 一般是干涉承載資源，**不保證等於輸出熱量或新生物質的能量來源**。

區分三個例子：
1. **暫時的魔法冰牆**：若仍依賴魔法結構，共鳴解除後可能消散或改變。
2. **普通冰牆**：將此世水合法冷卻成冰，結束術式後仍是普通冰，會依環境融化。
3. **永久真實物質**：若合法生成或轉移形成，完成後可以獨立存在；不能只因施法者離開便逆向消失。

永久物質生成的具體守恆與合法條件仍 TBD，尤其不能用「有 術式結構 就一定能製造任意品質的黃金」推翻經濟與物理限制。

## 6. 失效行為也受法則約束

**第 26 題 C：使用者已選。** 共鳴不足時，一個 術式結構 可能允許連續變弱、低於門檻後解除、安全關閉，或產生可解釋的控制事故。設計者可以建構失效處理，但不能寫 `safe=true` 就把已轉移的熱、動量或危險憑空刪除。

**第 27 題 C：已選。** 客觀法則決定可能性邊界，工程設計決定容錯、備援及安全終止。若善後依賴原共鳴，共鳴先斷後可能無法執行。

## 7. 這與 Combat 有何不同？

遊戲內術式卡、詠唱中斷、SP 和目標選擇是正式 Domain 語義；術式結構 是**世界的敘事模型**，不等於目前每張技能都需要儲存一張實際運算圖。要增加玩法必須另行核准並修改 `docs/combat/`，不能靠改此文件。

同一術式結構即使完全正確，若施術者的**個人共鳴橋樑受封鎖**，仍可能無法建立有效請求；這是執行條件受限，**不是術式結構突然變成非法**。詳見[共鳴封鎖](06_FORBIDDEN_RESONANCE_SEVERANCE.md)。
