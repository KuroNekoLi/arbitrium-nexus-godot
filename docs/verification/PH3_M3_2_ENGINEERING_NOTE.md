# Phase 3 M3.2 — Reaction Window, Draft/Queue, Confirm and JIT Skip

Authority: docs/combat/07 P1-D03/D04/D15/D16, 20 PRE3-R04 and CORE-04, 23 M3.2; Library 19 and 20. Requires M3.1 61/61 and M1-M2 249/249 preceding success. This work extends the authoritative M3.1 state; it does not create another independent game battle engine.

## New code and data contract

- m3/reaction/reaction_window_resolver.gd pins the Reaction Window to an already declared EnemyActionId. One action's multiple hit_count values share the same window_id. Window states DRAFTING -> RESOLVING -> CLOSED; NO_LEGAL_REACTION immediately produces a noninteractive CLOSED empty window. The actual character options shown here are reaction SPs only, NOT Guard/Protect yet.
- m3/reaction/reaction_eligibility.gd validates actor (including exhausted/incapacitated exclusion), actual owned hand CardInstance, target, public enemy target scope, trigger, current RP and MP, and cost/effect definition from explicit versioned Reaction catalogue. Unknown effects, Guard/Protect and M4 Concentrating exceptions fail closed (NOT_IMPLEMENTED), not accepted as if their outcomes existed.
- m3/reaction/reaction_queue_resolver.gd supports QUEUE_REACTION (same actor replaces earlier draft), REMOVE_REACTION, REORDER_REACTIONS, pure preview, CONFIRM_REACTIONS and PASS_REACTION. Queuing, preview, reorder and remove alter only M3 draft/metadata, NEVER RP, MP, card zones or M2 event/RNG state. Confirmation checks all already-known eligibility and aggregate budget before any payment. There is no UI time or clock and NEVER a forced timeout/pass. Reactions are executed in player-chosen order, one per actor, with JIT legality recheck. If an earlier reaction cancels its associated EnemyAction, dependent queued reactions emit ReactionSkipped(reason=TRIGGER_GONE) with no resource cost, discarded card or executed-actor quota; an explicitly independent fixture support reaction remains eligible.
- scripts/domain/m2/economy/resource_ledger.gd extends the existing authoritative resource model with PAY_REACTION_COST_FIXTURE: one atomic shared RP plus personal MP charge at Enemy Phase. scripts/domain/m2/integration/m2_domain_resolver.gd exposes COMMIT_REACTION_SP_FIXTURE: resolve fixed card-definition cost (never accept fee from command), pay via real resource ledger, move *that exact* owned hand CardInstance to discard via existing zone resolver, commit atomically or rollback. New M3.2 phase-engine command dispatch delegates to Queue; confirmed core events remain source-tagged and monotonic. Does not duplicate resource/cost invariants.
- test_m3_reaction_window.gd exercises multi-character queue, actor replace, reorder, remove, preview purity, explicit pass, stale/duplicate window/command, eligibility failures, cost and zone atomicity, per-window execution quota, RP persistence between windows, second EnemyAction ID, no phantom cards, zero-RP empty window, cancellation fixture resulting in skip and independent after-cancel support, same-seed Replay.
- CI .github/workflows/godot-m3-2-reactions.yml verifies official Godot 4.7.2 SHA512/import, M3.2 actual tests, ALL 61 M3.1 and ALL 249 M1-M2 regressions and four legacy scripts, with uploaded job logs.

## State transition and behavioral details

PLAY: END_PLAYER_PHASE (real M2 AP to RP) -> DECLARE_NEXT_ENEMY_ACTION -> OPEN_REACTION_WINDOW (requires actual published intent and target_ids) -> zero or more Queue/Preview/Reorder/Remove -> explicit CONFIRM_REACTIONS or PASS_REACTION -> COMPLETE_ENEMY_ACTION_FIXTURE -> next EnemyAction or END_ENEMY_PHASE. The M3.1 enemy-completion fixture is still backwards-compatible for M3.1's older non-reaction fixtures; newly authored actions marked requires_reaction_window=true may NOT complete without CLOSED window. Closed window can never be re-opened on the same action; its next action gets a different window ID. A closed Window cannot be confirmed, queued or charged again.

The proof fixtures are REACTION_SP definitions with versioned rp_cost, mp_cost, reaction_trigger and declared fixture_effect of CANCEL_ACTION_FIXTURE, NOOP_FIXTURE or INDEPENDENT_SUPPORT_FIXTURE. They **do not** implement actual damage, Spell Counter, Barrier, Guard, Protect or real M4 casting interruption. Basic Guard=1RP and Protect=2RP are approved but are **intentionally not executable until M3.3**, to avoid pretending their actual protection is in place. CAST_COMPATIBLE while Concentrating remains fail closed until M4 actual status and casting integration; no automatic whitelist.

The intentionally canceled EnemyAction fixture means remaining dependent reaction loses its trigger; JIT skip does not refund an already executed preceding reaction. An independent support fixture explicitly marked requires_active_enemy_action=false can still spend and resolve after cancellation. Known total budget deficit rejects confirmation before any spend. Unforeseen JIT resource/hand/status invalidity skips and logs reason instead of partially paying. M3.4 will own Smart/Always Ask/Quick policy, but all UI modes will share this same domain no-timer contract.

M3.2 alone is NOT M3 DOMAIN VERIFIED. M3.3 Guard/Protect, M3.4 UI mode, M3.5 complete domain replay remain gated. M5 status/hit/damage and real casting are NOT tested. No arbitrary Guard g=40% or maxAPDebt8 upgrades. Current execution status: M3_2_REACTION_QUEUE_DOMAIN_VERIFIED, based on the actual Godot CI attestation below.
